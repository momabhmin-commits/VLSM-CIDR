VLSM（可变长子网掩码）
VLSM 是 Variable Length Subnet Mask 的缩写，中文是 可变长子网掩码。

核心思想：
在同一个主网络（A、B或C类网）内部，可以使用不同长度的子网掩码进行子网划分。

解决的问题：IP地址浪费。
在没有VLSM的年代（使用固定长度子网掩码FLSM），一个网络中的所有子网都必须有相同的大小（即相同数量的主机）。这非常不灵活：

场景：一个公司有一个C类网 192.168.1.0/24（共254个可用地址）。

需要为点对点广域网链路（仅需2个IP）创建一个子网。

需要为一个拥有50台主机的部门创建一个子网。

需要为另一个拥有100台主机的部门创建一个子网。

FLSM（旧方法）问题：
如果使用固定的 /26 掩码（每个子网62个主机），虽然可以划分出4个子网，但点对点链路会浪费60个IP地址，而100台主机的部门一个子网又不够用。

VLSM（新方法）解决方案：
可以根据实际需求，使用不同长度的子网掩码：

点对点链路：使用 /30 掩码（255.255.255.252），提供2个可用IP，正好满足需求。

50台主机的部门：使用 /26 掩码（255.255.255.192），提供62个可用IP。

100台主机的部门：使用 /25 掩码（255.255.255.128），提供126个可用IP。

总结：VLSM实现了网络内部更精细的IP地址管理，极大地减少了浪费。它主要应用于一个组织或自治系统内部的地址规划。

CIDR（无类别域间路由）
CIDR 是 Classless Inter-Domain Routing 的缩写，中文是 无类别域间路由。

核心思想：
完全抛弃传统的A、B、C类IP地址的概念，允许将多个连续的 C类网络（或更一般地说，多个连续的IP地址块）聚合起来，形成一个更大的、单一的“超网”。

解决的问题：路由表爆炸和B类地址枯竭。
在早期“有类”寻址时代：

ISP如果要给一个公司分配400个IP地址，一个C类网（254个）不够，只能分配一个B类网（65534个），这造成了巨大的浪费，导致B类地址迅速耗尽。

互联网核心路由器的路由表需要为每一个C类网或B类网都维护一条路由条目，导致路由表规模急剧膨胀，影响性能。

CIDR解决方案：

路由聚合：一个ISP可以被分配一个大的地址块，例如 192.168.0.0/16。然后，它可以将其中的 192.168.0.0/24 到 192.168.63.0/24 这64个连续的C类网聚合起来，对外只需宣告一条 192.168.0.0/18 的路由即可。这极大地缩小了全球互联网路由表的规模。

灵活分配：ISP可以根据客户的实际需求，分配任意大小的地址块（例如 /28, /27, /26 等），而不受A/B/C类的限制。

总结：CIDR是一种在互联网骨干（域间）层面，用于路由聚合和灵活分配IP地址空间的技术。它通过“超网”的概念，解决了全球路由可扩展性和IP地址浪费的问题。

VLSM 与 CIDR 的关系与区别
为了更直观地理解，我们可以用一个表格来总结：

特性	VLSM（可变长子网掩码）	CIDR（无类别域间路由）
中文名	可变长子网掩码	无类别域间路由
核心思想	子网划分 - 把一个大的网络块划分成更小的、不同大小的子网。	路由聚合 - 把多个连续的小网络块合并成一个更大的超网。
应用范围	网络内部（域内），在一个组织或自治系统内部使用。	网络之间（域间），主要在互联网服务提供商之间使用。
解决的问题	IP地址浪费（在单个网络内部）。	路由表爆炸 和 B类地址枯竭（在全球互联网层面）。
比喻	切蛋糕 - 把一个大蛋糕（一个IP网段）切成不同大小的块（子网），分给不同食量的人（不同规模的子网）。	打包包裹 - 把很多个小包裹（小IP网段）打包进一个大箱子（超网）里，方便运输和识别（路由）。
它们之间的联系：

CIDR和VLSM都建立在“无类别寻址”这一共同理念之上。CIDR可以看作是VLSM思想的延伸和反向应用。

VLSM 是向下细分（子网划分）。

CIDR 是向上聚合（超网构成）。

它们共同标志着IP网络从“有类”时代迈入了现代“无类”时代，是当今IP地址管理和路由的基础。支持VLSM和CIDR的路由协议（如OSPF、EIGRP、BGP等）也因此成为现代网络的标准。
